# Changelog

## [0.1.0]

- **First version under the new name Atelier Manager** (formerly OnAirDeck Unity Manager 0.6.1). The package id `com.studioraming.manager`, the namespaces, `onairdeck.license` and the EditorPrefs keys are unchanged. Display name, README titles (EN/KO/JA), user-facing messages and release file names (`Atelier-Manager-<version>.unitypackage`, `Atelier-Manager.unitypackage`) use the new name; the zip stays `com.studioraming.manager-<version>.zip`.
- **Old Assets install is moved with consent before a package install (contract v9).** `LegacyInstall` (no UnityEditor) finds an older copy of the product under `Assets/` from four sources (`OnAirDeckConfig.LegacyAssetFolders`, the incoming package.json `"atelier": {"replacesAssetFolders": [...]}`, an `atelier.product.json` marker with the same `license_id`, GUID collisions under `Assets/`), applies guard rails (only below `Assets/`, never `Assets` itself, never a folder holding a package.json, `PathSafety.IsInside`), asks through a confirm callback (`PackageInstallService.InstallAsync(..., confirmLegacy)`), moves the items and their .meta to `Library/OnAirDeck/Backup/legacy-<timestamp>/`, and puts them back when the install fails or collisions remain. `LegacyInstallDialog.Confirm` is the `EditorUtility.DisplayDialog` callback (ko/en/ja in `LegacyInstallText`). A background caller never moves files: it throws `LegacyCleanupRequiredException` (text: old install needs clean-up). `BatchActions.InstallAll` shows one combined dialog; "do not install" leaves out only the flagged items. `GuidCollisions.Refusal` names a foreign package that holds the GUIDs ("cannot be installed in a project that has <package>") instead of "Remove or migrate them first"; `InstalledPackages.LegacyRefusal` stays only as the transaction's last guard.
- **v9 follow-up.** A GUID-only find moves only product files: from each colliding file it walks up to the highest folder under `Assets/` in which every asset collides with the incoming package and moves that folder; with none, the colliding file and its .meta move alone (a user's own files in a shared folder stay). Every move writes `backup-manifest.json` into its `Library/OnAirDeck/Backup/legacy-<timestamp>/` folder first (from/to, package, version, state moving|moved|installed|restored, timestamps); `LegacyMove.PendingRestores()` lists moves whose install never finished and `LegacyMove.RestoreFromManifest(path)` puts them back (refuses when an original place is occupied, never throws).
- **Request header.** Every request (including `plugin-version` and the publishable-key calls) sends `X-Atelier-Manager: 1`, so the server can tell this line from the old one.
- **Own products and licenses.** `PurchaseItem` (the purchase list entry) and `LicenseEntry` gain `seller_id`, `seller_name`, `thumbnail_url`, `source`, `description`, `product_url`; `PurchaseItem` also `category`, `purchased_at` and `versions[]` (`PurchaseVersion`: `file_id`, `version`, `released_at`, `notes`, `size_bytes`). An own product downloads with `product_id` + `file_id`, and its license is issued with `product_id` (field name assumed, see the contract).
- **License files for seller licenses.** `LicenseService.EnsureLicenseFilesAsync(token, licenses)` issues or renews (2 days before expiry) `Assets/StudioRaming_Onairdeck/<license name>/onairdeck.license` through `plugin-license { license_id, client }` for every license whose package is installed in the project by any route (`InstalledPackages.IsInstalled`: Packages folder, manifest.json, vpm-manifest.json). Called after a list refresh (`PurchaseWatcher`, `UpdateCheckService`) and after a license-version install; refusals go through `DeviceLimitNotice`.
- **Dependencies from the account first.** `CollectDependenciesAsync` resolves installed, then a license version of the account (same package name and version, device gate applies), then the trusted VPM listings (`DependencyResolver`). A missing one throws `DependencyUnavailableException` (`Kind`: NotPublishedYet or GetOnAtelierFirst). `InstallAsync` takes the caller license list (optional last parameter).
- **`PurchaseWatcher`**: refreshes on editor focus, window focus and every 5 minutes while the window is open (at most once per 60 s, signed in only, silent on failure); keeps seen entry ids per account in EditorPrefs (the first load marks everything seen) and raises `NewEntriesFound`.
- **`FavoritesStore`** (EditorPrefs, per signed-in user id, `Changed` event), **`ThumbnailCache`** (https only, 64 MB cap with oldest-first eviction, quiet failure), **`UpdateCheckService`** (once per editor session and every 6 hours, signed in only, one Console line, never installs) and **`BatchQueue`** / `BatchActions` (sequential, "2/3" progress, cancel after the current item, per-item results, device-limit and update-required refusals pause through `DeviceLimitNotice`, Unity packages import without the import window).
- **Device limit (client side).** Every request that carries a session token now sends `X-OnAirDeck-Device` (SHA-256 of `onairdeck-device-v1|` + `SystemInfo.deviceUniqueIdentifier`; the raw id never leaves the PC), `X-OnAirDeck-Device-Name` (computer name, 64 characters, URI-escaped) and `X-OnAirDeck-Device-Platform` (`Windows`, `macOS`, `Linux`). `Editor/Api/DeviceIdentity.cs` (Unity part) and `DeviceIdentityCore.cs` (pure part, headless-checked).
- **Error model.** Error bodies are read once in `ThrowIfFailed`: 409 `device_limit` becomes `DeviceLimitException` (refused licenses and the devices holding seats), 426 `manager_update_required` becomes `ManagerUpdateRequiredException`, any other failure one `ApiException` (status, server error code, short English message; the raw body is kept in `ResponseBody`, no longer in the message). 401 still means `SessionExpiredException`.
- **Devices API.** `OnAirDeckApi.GetDevicesAsync` and `ReleaseDeviceAsync` (`plugin-devices`); `LicenseEntry` gains `max_devices`, `devices_used`, `this_device`.
- **`DeviceLimitNotice`.** Download, package install, license issue (including the one after a download) and silent license renewal report a device-limit or update-required refusal into one observable state with the action to retry after a release, instead of only logging it. The window UI for it comes later.
- **Packaging.** `build_manager_packages.py` also writes `Atelier-Manager.unitypackage` (same bytes as the versioned file) so `releases/latest/download/Atelier-Manager.unitypackage` is a stable link. CompileCheck references `UnityEngine.TextRenderingModule` (the theme uses `FontStyle`).
- 11 more headless checks (device hash vector, name, platform, error parser).
- **DRM products shipped as .unitypackage (contract v8).** A license counts as installed when a VPM package of it is installed or an `atelier.product.json` with its `license_id` exists under `Assets/` or `Packages/` (`ProductMarkers`, one scan per refresh; hidden and `~` folders skipped; malformed markers ignored). An existing `onairdeck.license` under `Assets/StudioRaming_Onairdeck/` keeps renewing without a package (by the id inside it, in the folder it is in). A marker without a license file gets one on the next background ensure (no reactivate header). New public `OnAirDeck.UnityManager.AtelierManagerApi.RequestLicense(string licenseId)` for lock screens (called by reflection): opens the window, signs in if needed, issues that license as a user click, fire and forget, never throws; the last requested id is in `AtelierManagerApi.PendingLicenseId` for the window to select.
- **Unity floor lowered to 2019.4** (`package.json`). Editor and License assemblies compile with 0 errors on 2019.4.31f1 and 2021.3.18f1. `PackageInfo.GetAllRegisteredPackages` (feedback environment) and `Client.Resolve` (install, recovery) are guarded with `UNITY_2021_1_OR_NEWER` and have a folder-based fallback / rely on the refresh on older editors.
- **Review fixes.** A license file issued to another account (or PC, when the payload carries a device) is reissued; a background refusal no longer overwrites the retry a paused batch installed (retries chain, same-key ones replace each other); cancelling while an item runs no longer leaves the batch waiting after a refusal; long license names keep their id suffix; an account switch during a purchase request drops that response; Windows reserved names (CON, NUL, COM1...) get a `_` prefix; the seen-entries list keeps the newest 1000 keys.
- **Released device (contract v7).** `X-Atelier-Reactivate: 1` is sent only on requests a user click started (install, update, download, batch, the reactivate button). 409 `device_released` becomes `DeviceReleasedException`; background paths stay silent and `DeviceLimitNotice.Current.Kind == DeviceReleased` shows one bar (`DeviceReleasedText`, ko/en/ja) whose button runs `RetryAsync()`.
- **Inventory gate for old installs.** Sources 1-3 (config table, package.json `replacesAssetFolders`, product marker) never move a folder unless a product handler vouches (`ILegacyHandler`) or the package's own inventory (`atelier.legacyInventory`, provisional JSON `{"files":{path:sha256}}`) matches every file; otherwise the plan says "old install needs clean-up" with the folder and the unmatched paths. Source 4 (GUID) is unchanged.
- **Renewal refusals are readable.** `LicenseRenewalStatus.All/For/Changed`: per license the refusal code (`api.Code` or `http_<status>`), cleared on success, set by `EnsureLicenseFilesAsync` and `IssueSellerLicenseAsync`.
- **Install a non-VPM license version by id.** `LicenseVersionInstall.InstallAsync(token, license, version, licenses, onProgress, cancel, interactiveImport, userInitiated)`: `plugin-download { license_version_id }`, .unitypackage through `PackageImportQueue` (paths and GUIDs kept, no import window by default), zip extracted, license file issued afterwards. The server returns one file `{url,file_name}` without a hash; the Manager checks `file_size` where it has one.
- **Dev-only server override** under the compile define `ATELIER_DEV_SERVER` (EditorPrefs `Atelier.Dev.FunctionsUrl`, `Atelier.Dev.SiteUrl`, `Atelier.Dev.LicensePublicKeyPem`, `Atelier.Dev.DeviceSalt`; loopback http downloads allowed). Without the define the prefs are never read (Verification check).
- **MingToon legacy hand-off.** With the old `Assets/StudioRaming/MingToon` and no `Packages/com.studioraming.mingtoon`, a user click and a dialog start `MingToonLegacyCleanup`: both files of the license version (`...-update.unitypackage` and the package zip) are downloaded and checked first, the installer must say `managerCleanup: true`, then `ProjectSettings/MingToonInstaller/manager-request.json` is written and the installer imported. The Manager waits (reload-safe state in `Library/OnAirDeck`, no refresh, resolve or import), reads `manager-result.json` matched by `requestCreatedUtc`, installs the zip to `Packages/` after `LegacyRemovedForManager` and calls `Client.Resolve`. `LegacyHandoff.Status(package)` returns None, Pending, Done or Stopped(reason). Background and batch never start it. `OnAirDeckConfig.NeverMoveAssetFolders` (presets, generated files, installer, MLC) is never part of any move.

## [0.6.0] - 2026-10-27

Kind popup (Bug / Feature request / Question), a message of up to 4000 characters, an optional error code of up to 200, a toggle **Attach recent Console errors (N)**, the environment shown read-only before sending, **Send** (disabled while sending or while the message is empty or too long) and the result below it with a short reference. - **Console error buffer** (`Editor/Feedback/ConsoleErrorBuffer.cs`, `[InitializeOnLoad]`): `Application.logMessageReceivedThreaded` feeds a thread-safe ring buffer of the last 50 Error / Exception / Assert entries (message, first 20 stack lines, time). Nothing is sent unless the toggle is on; the attachment keeps the newest entries within 20 KB and replaces the user's home folder with `~`.
- **`FeedbackClient`** (`Editor/Feedback/FeedbackClient.cs`) posts `{ kind, message, errorCode, consoleLog, unityVersion, managerVersion, os, packages }` to the new `plugin-feedback` edge function with the plugin session token, like the other calls. `packages` lists the registered `com.studioraming.*` / OnAirDeck packages as `name@version` (the Manager included).

## [0.5.0] - 2026-10-25

- **StudioRaming Editor Theme.** The window is drawn with the family theme used by MingPainter and MaskMaker (`Editor/UI/Theme/StudioRamingEditorTheme.cs`, namespace `OnAirDeck.UnityManager.Theme`, `SRProduct.OnAirDeck` = the Mint accent): header band with the OnAirDeck mark, cards for packages and purchases with status badges (Downloaded / Update available / Up to date / Not installed / Requested), themed buttons (the row's main action is the primary one), help boxes by tone, the themed progress line and search field. Both editor skins; no layout or behaviour change.
- **Packages section.** `plugin-purchases` now also returns the seller licenses the account may download (`licenses`, each with its versions). For versions whose file name is `<package>-<version>.zip` the window shows, per package, the installed version (from `Packages/<name>/package.json`), the newest version, **Install** / **Update** and a picker for older versions. `plugin-download` accepts `license_version_id` for these (`OnAirDeckApi.RequestLicenseVersionDownloadAsync`).
- **One install transaction** for a package and its exact dependencies (`Editor/Packages/`). Zips are validated (any unsafe entry fails the whole package; root `package.json` name and version must equal the listing; `vpmDependencies` must pin exact versions as `"X"` or `"=X"`, copied verbatim into `locked.<name>.dependencies`) and dependencies come only from a fixed list of trusted VPM listings (the stable MingToon listing, then the preview listing, the only one with prerelease versions), verified by SHA-256. The zips are staged under `Temp/OnAirDeck/`, a journal is written to `Library/OnAirDeck/install-journal.json`, the contents of each existing `Packages/<name>` go to `Library/OnAirDeck/Backup/<name>-<oldVersion>-<time>` and the new contents are moved in (the folder itself stays; a package not installed before arrives as a whole folder). A failure undoes the moves in reverse order; an interrupted install is rolled back on the next editor load. Files the new package does not contain are not carried over and are listed in the result. Existing entries of `Packages/vpm-manifest.json` are updated (backed up first, nothing added, unknown keys kept), then `Client.Resolve()` and `AssetDatabase.Refresh()` run once. A package installed the old way under `Assets/` (MingToon: `Assets/StudioRaming/MingToon`) is refused until it is migrated.
- **GUID collision guard.** Before any move the `.meta` GUIDs of every zip are matched against `Assets/` and the embedded package folders (not the ones being replaced). Stray files inside an installed package, such as an old add-on `.unitypackage` import inside the core folder, are removed by reinstalling that package at its current version from a trusted listing in the same transaction (reported, kept in the backup). Any other collision refuses the install before any change, listing up to 10 paths. Two zips of one install that share a GUID are refused as well.
- **Mismatch banner** when an installed package's exact dependencies disagree with the installed dependency version; its button names the versions it will install.
- **`OnAirDeckPackages.OpenAndFocus(packageName)`**, a public entry point other packages can call to open the window on their own row.
- **Git-free install and self-update.** `Tools~/Packaging/build_manager_packages.py` builds `OnAirDeck-Unity-Manager-<version>.unitypackage` and `com.studioraming.manager-<version>.zip` and self-checks them. An embedded Manager updates itself from the release's `download_url` through the same validation and transaction; git and registry installs keep the Package Manager update. `VersionResponse` also reads a top-level `download_url`.
- `OnAirDeck.License` lets the Manager assembly use its internal `MiniJson` (`InternalsVisibleTo`).
- **Held files during the swap.** Windows refuses to rename a folder while a file inside it is open, and antivirus briefly opens freshly extracted files (with Defender on, 8 of 80 MingToon add-on extractions failed the first move; each cleared within 135 ms). Every folder move of the transaction and its rollback now retries such a lock for up to 5 seconds; a missing source, a destination in the way or a move across volumes still fails at once. Found by the URP update test bed, where the first add-on install failed and rolled back.
- **Updates keep the package folder.** Unity watches each embedded package folder and keeps watching it after a rename. The first update test on Unity 2021.3.45f2 renamed the old MingToon folders to the backup and put new ones in their place; the next `AssetDatabase.Refresh` (and Unity's own refresh after `Client.Resolve`) then waited forever in `DirectoryMonitorWindows::Sync`, with the editor frozen at no CPU. A small repro project showed the same freeze for that pattern only: moving contents, deleting the folder, or renaming it away with nothing in its place all refresh normally. An update now moves the old contents to the backup and the new contents in, and the rollback does the reverse, keeping the folder. The journal (format 2) records which contents the folder holds so a crash between any two moves is undone; an unfinished journal of the older format is set aside with a message instead of replayed.
- **Journal hardening.** The journal is written to a temporary file and then put in place in one replace, so a crash while it is saved leaves the previous journal, never part of one (it used to be copied over the old file). Recovery refuses an unfinished journal whose package name is not a package name, whose stage folder is empty, or whose entries lack a string `phase`; and when a journal says a package was not touched while that package's backup holds files, recovery moves nothing and leaves the journal unfinished with a message to check by hand.
- **Window copy.** A BOOTH-claim license with packages but no OnAirDeck order no longer shows "No purchases yet" under its own packages. The install confirmation states the refund rule only for licenses bought on onairdeck.com. A message (an install report, for one) has a **Dismiss** button, and a separator sets the **Open onairdeck.com** button apart from it. Full-width buttons wrap their label, so the button that fixes a version mismatch no longer cuts off both package names in the narrowest window.
- 29 more headless checks (65 total), including GUID collision cases: zip validation cases, SHA-256 and HTTPS gates, the listing lookup, the transaction with a failure injected and a crash simulated at every fault point (each journal save included), rollback retry and a rollback crashed at every fault point, a file held open during the swap, a watcher on the package folder that must still see new files after an update, a rollback and a recovery, the vpm-manifest edit, the legacy refusal, tampered journals (one field changed per case, each refused for its own reason), a journal that contradicts the backup, the mismatch finder.

## [0.4.0] - 2026-10-15

- **Runtime license check for sellers.** New assembly `OnAirDeck.License` (folder `License/`, Editor-only, no UnityEngine dependency): `OnAirDeckLicense.Check("<product id>")` finds the product's `onairdeck.license` under `Assets/StudioRaming_Onairdeck/`, verifies the RSA signature with OnAirDeck's embedded public key, and checks the product, the signed-in account (the Manager's session marker) and the expiry, all offline. The result carries a `LicenseStatus` reason (`NotSignedIn`, `LicenseMissing`, `InvalidSignature`, `Expired`, `UserMismatch`, ...) and a message, so a seller's tool can say "sign in with OnAirDeck Unity Manager" instead of failing silently. Results are cached for 30 seconds so the check can run from `OnGUI`. `LicenseVerifier.Verify` exposes the pure verification for custom setups.
- After writing a license the Manager runs the same check and logs a warning if the file would not pass it, so a key or format mismatch shows up immediately.
- Seven more headless verification checks (35 total): a license issued by the real service verified with the embedded key, tampering, malformed input, JSON escapes, and the file/marker lookup with its cache.
- Honest limit, unchanged: a client-side check deters sharing; it cannot stop someone who decompiles and edits the calling assembly.

## [0.3.0] - 2026-10-15

- **License file.** After a download the Manager asks OnAirDeck for a signed license and writes `onairdeck.license` into the product folder (`Assets/StudioRaming_Onairdeck/<Product>/`). Licenses live 7 days; the Manager re-issues them silently for installed products when the window opens and the file is missing or within 2 days of expiry. Issuing a license never counts as a download.
- **Session marker.** While signed in, `%LOCALAPPDATA%/OnAirDeck/session.json` holds the signed-in user id (never the token). Removed on sign-out and when the server rejects the session. Together with the license file it lets a seller's asset verify "signed in + licensed" without network access.
- **Update check.** On window open the Manager asks `plugin-version` once per Editor session. A newer published version shows an **Update** button (git/registry installs switch to the published git URL through Package Manager; local-disk installs are told to update their copy). A version below the server's minimum blocks sign-in until updated.
- Four more headless verification checks (license parsing, refresh window, write confinement, session marker).
