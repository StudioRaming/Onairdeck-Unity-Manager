## [0.1.4]

- **MingToon installed with VCC moves to the Manager.** MingToon is no longer updated through VCC (owner decision 2026-10-31). When `Packages/vpm-manifest.json` still lists the MingToon core or URP add-on and its folder is in `Packages/`, a bar says so with **Move to the Manager**. The move copies the file to `Library/OnAirDeck/Backup/vcc-move-<time>/` and takes the packages' entries out of both `dependencies` and `locked`; the package folders, every other entry and key, and the project's own files (materials, presets) stay. **Undo** puts the entries back at the folder's current version, **Keep it** ends the offer. Both entries go because the VRChat resolver (vpm-core-lib 0.1.29) treats an entry in either one whose version differs from the folder as missing and puts the listed version back over the folder on the next project load; with no entry it leaves the folder alone (`VpmMigration`, `OnAirDeckConfig.ManagerOnlyVpmPackages`).
- **One row for one package.** Two licenses of the account that carry the same package (MingToon's free Core license and the commercial one) are one row: the license with more rights, with the other license's newer versions (and their installer files) added. Every held license still gets its own license file; a license with a device limit keeps its own row.
- **An import that grants several licenses installs all of them.** A one-button import of an item that grants several licenses (a MingToon Founders edition: Core, URP add-on, MLC) installs every one under the one confirm: an add-on (`<core>.<suffix>`) before its core, so it brings the exact core it pins and the core's own step is skipped; file-only licenses last. Script reloads wait until the last step. A step that does not end at once (failed, declined, or waiting for an import or a hand-off) ends the run with its result; the rest can be installed from the list.
  A package that a package installed earlier in the run needs at an exact version (directly, or through packages it depends on, also behind a range) gets exactly that version; when that version is not offered, the pins disagree, or a package installed in the run cannot be read, the run stops with `install_failed` and says why.
- **The Manager updates itself.** The window asks plugin-version when it opens (not again within 10 minutes) and once a day while it stays open, and installs a newer release by itself at a safe moment (no install, batch, hand-off, import request or queued `.unitypackage`, not compiling, not in play mode): an embedded copy takes the release zip, a git install switches to the release tag. `Library/OnAirDeck/self-update.json` is written first; the new version shows "업데이트됨 a → b" once ("최신 버전으로 업데이트했어요" when the first check of a fresh install found it, so an old `.unitypackage` or a pinned git URL ends on the latest). When the new code does not compile, the old code, which Unity keeps loaded, puts the previous folder back from the install backup (git: the previous package id) and says so; that release is installed again only by a click. A git working copy, or a folder linked to one, is never replaced. A required update keeps its blocking screen and is installed the same way. `Tools~/Packaging/check_release_assets.py <tag>` checks that a release carries the version-less `Atelier-Manager.unitypackage` (the same bytes as the versioned one) and is the latest release.
- **A bar with a long text is as tall as its text.** The bar above the list measured its text without wrapping, so a two-line text was clipped.
- **State files are replaced again when Windows holds them for a moment.** Two installs in a row rewrite the install journal within milliseconds; the second `File.Replace` could fail with "unable to remove the file to be replaced" (seen in Unity 2022.3). `AtomicFile` and the vpm-manifest.json write now try again for about a second.
- Verification: headless checks for the move (find, both entries out, formatting, backup, undo at the current version, refusals, keep), the merged row, the install order and the pins; EditMode tests for an item with several licenses (add-on first with its pinned core, a core already at the pin stays, two unrelated packages).

## [0.1.3]

- **The Manager's own errors open the report card by themselves.** `ManagerErrorWatch` offers a card (title "Atelier Manager에서 오류가 났어요") for an exception in the Console whose first frame that is not Unity's or .NET's is the Manager's (OnGUI, an `async void` step that let it escape, an editor callback), for a faulted task nobody awaited (`TaskScheduler.UnobservedTaskException`), for an exception that ends a background thread (`AppDomain.UnhandledException`), and for an unexpected exception the window's own steps catch: sign-in, sign-out, the product list, license refresh and renewal, the update check, the self-update, the device screens, and the background purchase refresh and update check. A server, network, cancel or sign-in failure is not a bug: it keeps its red message and the "Send a bug report" button only. Everything goes through the same card as an install error: shown redacted (`FeedbackText.Redact`), one entry per signature, each exception judged once per domain even when it repeats on every repaint, and sent only on the Send click (code `manager.exception`).
- **The ask screen shows the attached Console errors before sending.** With "Attach recent Console errors" ticked, "Show the attached errors" opens the exact text that goes with the message (redacted and cut as it is sent).
- **One-button import from the website ("Unity로 가져오기").** The Manager lists `plugin-import-requests?client=unity` when the editor regains focus, when its window is focused and every 60 s while the window is open, never within 15 s of the last poll, signed in only, and not while scripts compile, in play mode, during a legacy hand-off or while the window is busy. It claims the newest request and always asks in a dialog that names this project (Import / Not this project / Cancel, with the first-download refund warning), then runs the same install path as a click (download a purchase, install the offered package or file version; refund lock, device gate and license issue unchanged) and reports `done`, `failed` (with a code), `declined` or `release`. A `.unitypackage` is reported only after its import ends; a hand-off install after its package version is in. "Not this project" gives the request back and is not asked again in this editor session. The held request is kept in `Library/OnAirDeck/import-claim.json`, so a script reload or an editor restart still ends in a report; a long install renews its lease every 5 minutes, and a lease lost while the dialog was open installs nothing. Contract: Vdesk `plugin-import-requests` v1 (server PR #864).
- **Project check.** On window open, on Refresh, when the account's package licenses change and after every fix, the Manager checks the project on a worker thread and a bar says what it found: files that share a GUID (grouped by where the copies live), an old copy of a product under `Assets/` beside its installed package, two assembly definitions or managed DLLs with one assembly name, and a package that is both under `Packages/` and in `Packages/manifest.json`. The "Project check" screen lists them with fixes: **Move to backup** (to `Library/OnAirDeck/Backup/legacy-<time>/` through the install's own guard rails and backup manifest; a folder moves whole only when everything in it is a copy), **Reinstall** (the normal install path with its own confirm), **Remove from manifest.json** (the file is backed up first; only that entry changes, order, other entries and line ends stay, and the result is read back before it is written), and **Show in Project**. Every clean-up is listed with **Undo** and **Keep it** until one is chosen. Only packages Unity resolved count (an old version left in `Library/PackageCache` does not), a DLL counts only when its Editor settings (OS, CPU) load it here, and every fix first checks that what it touches still holds what the check saw (a file added to a checked folder, a changed manifest entry or a removed package stops it and runs the check again). A check younger than 10 minutes is reused after a script reload.
- Verification: headless checks for the Manager error rules, the import rules (poll timing, request choice, confirm, waiting, resume after a reload, error handling) and the project check (each conflict kind, the move, undo and keep, manifest edits); EditMode tests in `Tools~/EditModeTests` for the Console, task and catch hooks and the import flow end to end against a loopback fake server (needs `ATELIER_DEV_SERVER`).

- **Install error report card.** When an install or import of a product breaks, the Manager window shows a card at its top ("설치한 <product>에서 오류가 났어요") with the reason, the exact text that would be sent (expandable), an optional note and the buttons Send / Don't send. Nothing is sent without the click; Send is disabled while signed out and the server's refusals (429 after 5 sends, others) are shown on the card. It opens from: a failed download, package install or file-version install, a failed batch item, a failed `.unitypackage` import, a failed recovery of an interrupted install, and the new "Send a bug report" button next to any red message (that one also reopens a card that was dismissed). A closed window is opened without taking focus.
- **Watch after an import.** `InstallErrorWatch` runs from the start of a `.unitypackage` import or a package install until the script compile that follows ends, plus two minutes, and reports compile errors whose file is one of the import's own paths (every imported file and its `.meta`; a folder only when the import created it, whatever its children, so one file into a shared Assets/Editor, or an empty Assets/Editor entry, does not claim its neighbours; whole path segments) (`install.compile_failed`), console errors that name an imported path, and exceptions whose stack runs through the product's own assemblies (asmdef or DLL names under the imported paths) (`install.exception`). Folders come from the package's folder entries (`folderAsset: yes` in the asset meta). A failed Manager-side step is `install.manager_failed` (a handled refusal) or `install.exception` (an unexpected exception). License-gate texts, user cancels, device-limit and sign-in states and errors of other packages never make a card. The watch state is kept in SessionState, so it survives the domain reload a successful compile causes. Every import or package install is a job of its own with its paths, compile state and end time: its two minutes are fixed by the first compile that ends (later compiles do not extend it), a compile that is still running is waited for up to one hour, a second package of the same product joins the running watch without touching the first job, and a cancelled import removes only its own job.
- **One report per product, shown once.** Several errors of one import join one card (compile errors first, then exceptions); every error keeps its own code, product id and signature, and every card has an id of its own, so a new card of the same product and version never shows or sends an older card's text. A signature (license id | error code | the first error line without digits and paths | for a stack trace, its first frame that is not `UnityEngine.`, `UnityEditor.`, `System.` or `Mono.`) that was sent or dismissed is kept in `Library/OnAirDeck/InstallErrorReports.txt`. An automatic card is not shown again for it; the button next to a red message can reopen a dismissed one, and says "같은 오류는 이미 알려 주셨어요." for one that was sent.
- **One redaction for everything that is shown and sent.** `FeedbackText.Redact` finds every rule's matches on the original text, merges overlapping ones and replaces once, so a rule never runs on another rule's output and a second pass changes nothing. It hides absolute paths (drive letters, UNC, `//host`, 8.3 short names, `file:///`, POSIX, either slash, JSON-escaped): inside the Unity project folder as `Assets/...`, `Packages/...`, `Library/...`, elsewhere as `<path>/<file name>`; the host name and Windows user name anywhere (`<host>`, `<user>`; one- and two-character names only as a whole word); e-mail addresses (`<email>`); runs of 20+ base64 or hex characters and JWTs (`<token>`); the value of `key=value`, `key: value` and `"key": "value"` whose key contains token, secret, password, auth, session, cookie, key or sig, and `Bearer ...` (`<redacted>`); and Steam ids (`<steamid>`). The whole text is redacted before any cut. `FeedbackClient.Build` redacts the message, the error code, the log and every package entry of every send (also the 문의하기 screen's); the card's title, reason, preview and error texts, and the 문의하기 screen's package row and error, show the redacted value. Send freezes the displayed text: only the entries that made it into the excerpt are recorded as sent and leave the card, and every waiting entry with a sent signature goes with them.
- `FeedbackClient.Build` takes the console text instead of a flag, and `FeedbackEnvironment.Collect` can report a given `name@version` list, so the 문의하기 screen and the card share one send path. New headless checks in `Tools~/Verification` (redaction, signature, entries, card identity, path attribution, owned paths and the archive's folder entries, excerpt, watch deadlines and jobs, ledger).

## [0.1.2]

- **A .unitypackage product shows its new version.** A product installed from its files had no version the Manager could read (the `atelier.product.json` marker holds only the license id, and Unity keeps the packed file times), so it always showed as up to date. The Manager now records what it installed in `ProjectSettings/OnAirDeck/installed-versions.json` (`InstallRecords`: license id, version id, label, release time; atomic write; travels with the project). Loose files are recorded once copied, a .unitypackage once its import finished (`PendingImportRecords` in SessionState survives the reload; a cancelled or failed import records nothing). The window compares the record with the offered file: the same version is up to date, a later release is a new version (Update), a recorded version newer than the offered one is installed. An installed product with no record (installed by 0.1.1 or by hand) shows "버전 확인 필요" with Install Latest instead of a false "up to date"; one install through the Manager records it. A version is not recorded when nothing of it was placed. A listed recorded version is compared by its row (newest first), so a file without a release time still compares. A project on a preview or beta file is offered the newest file of all, as packages are; when the recorded version is newer than the one offered, the header has no install button (it would install an older file) and the Versions rows remain; an unreadable release time reads as unknown. Saving over an unreadable record file keeps its last copy as `.prev`. Limits: a product without a marker (packaged before contract v8) stays "not installed" whatever the record says, since the record cannot tell whether its files are still there; file products show "new version" on their row and in the New filter, but the "N updates" bar and "Update all" count packages and purchases only.
- **Dates in the computer's time zone.** Release, purchase and device "last used" dates were the UTC date, so from 00:00 to 09:00 KST they showed the day before.
- **Install confirmation says what happens.** A first install no longer promises a backup; installing a .unitypackage or loose files over an existing copy says the files are overwritten without a backup (only a package update keeps the old version in `Library/OnAirDeck/Backup`).
- **WARUDO products are no longer listed.** `plugin-purchases?client=unity` sends every purchased line item; one without Unity files (a WARUDO product, or a product whose files now come through its seller license) was listed as "not downloaded" with nothing to install. `PurchaseItem.ShownInUnity` now leaves an item with an empty `files` list out of the list and the new-purchase notice, also when it was downloaded (that count is shared with the WARUDO app); the update count needs Unity files. A body without the `files` field keeps the item. Such a purchase reappears once its product has Unity files.
- **The message after a license install.** A license version's .unitypackage imports without Unity's import window, but the message asked to press Import there; it now says Unity imports it next.
- Verification: 5 new headless checks (file version state, record file, pending import record, local dates, purchases without Unity files). The handoff reload check compared a fixed 2026-10-29 time with the real clock and failed from then on; it now uses the current time.

## [0.1.1]

- **A product update whose files keep the installed time is re-imported.** A .unitypackage carries its file times and Unity keeps them; an overwritten file whose time did not change was not re-imported, so an update packed with the same fixed time as the installed version left the old DLL loaded. `PackageImportQueue` records the package files that already exist before the import and force-imports those that still carry the same time once it completes (a fresh install re-imports nothing). The tar.gz reader is shared in `UnityPackageArchive`.
- **Versions tab.** The chips and the date have a gap, and the notes shown open are those of the version Install picks.
- **Preview, beta and hotfix builds are told apart.** A package version with a semver prerelease part (`0.1.15-preview.1`, `-beta.N`, any other such as `-rc.1`) gets a Preview, Beta or Pre-release chip in the Versions tab and is no longer the default Install or Update for a project that runs a release; it is installed when picked by hand. A project already on a prerelease is offered the newest of all (the update check already worked this way), and a package with no release yet offers its newest prerelease. A hotfix is an ordinary patch release, since semver has no hotfix rank; a seller label with the word hotfix, 핫픽스 or ホットフィックス adds a Hotfix chip. A file version (.unitypackage) has no version to parse, so the same words in its label decide (whole words, so "Preset" is not a preview) and the newest non-prerelease file is the default. Rules in `Editor/Packages/BuildKind.cs`; checks in `Tools~/Verification` (build kinds, offered version).

## [0.1.0]

- **First version under the new name Atelier Manager** (formerly OnAirDeck Unity Manager 0.6.1). The package id `com.studioraming.manager`, the namespaces, `onairdeck.license` and the EditorPrefs keys are unchanged. Display name, README titles (EN/KO/JA), user-facing messages and release file names (`Atelier-Manager-<version>.unitypackage`, `Atelier-Manager.unitypackage`) use the new name; the zip stays `com.studioraming.manager-<version>.zip`.
- **Old Assets install is moved with consent before a package install (contract v9).** `LegacyInstall` (no UnityEditor) finds an older copy of the product under `Assets/` from four sources (`OnAirDeckConfig.LegacyAssetFolders`, the incoming package.json `"atelier": {"replacesAssetFolders": [...]}`, an `atelier.product.json` marker with the same `license_id`, GUID collisions under `Assets/`), applies guard rails (only below `Assets/`, never `Assets` itself, never a folder holding a package.json, `PathSafety.IsInside`), asks through a confirm callback (`PackageInstallService.InstallAsync(..., confirmLegacy)`), moves the items and their .meta to `Library/OnAirDeck/Backup/legacy-<timestamp>/`, and puts them back when the install fails or collisions remain. `LegacyInstallDialog.Confirm` is the `EditorUtility.DisplayDialog` callback (ko/en/ja in `LegacyInstallText`). A background caller never moves files: it throws `LegacyCleanupRequiredException` (text: old install needs clean-up). `BatchActions.InstallAll` shows one combined dialog; "do not install" leaves out only the flagged items. `GuidCollisions.Refusal` names a foreign package that holds the GUIDs ("cannot be installed in a project that has <package>") instead of "Remove or migrate them first"; `InstalledPackages.LegacyRefusal` stays only as the transaction's last guard.
- **v9 follow-up.** A GUID-only find moves only product files: from each colliding file it walks up to the highest folder under `Assets/` in which every asset collides with the incoming package and moves that folder; with none, the colliding file and its .meta move alone (a user's own files in a shared folder stay). Every move writes `backup-manifest.json` into its `Library/OnAirDeck/Backup/legacy-<timestamp>/` folder first (from/to, package, version, state moving|moved|installed|restored, timestamps); `LegacyMove.PendingRestores()` lists moves whose install never finished and `LegacyMove.RestoreFromManifest(path)` puts them back (refuses when an original place is occupied, never throws).
- **Request header.** Every request (including `plugin-version` and the publishable-key calls) sends `X-Atelier-Manager: 1`, so the server can tell this line from the old one.
- **Own products and licenses.** `PurchaseItem` (the purchase list entry) and `LicenseEntry` gain `seller_id`, `seller_name`, `thumbnail_url`, `source`, `description`, `product_url`; `PurchaseItem` also `category`, `purchased_at` and `versions[]` (`PurchaseVersion`: `file_id`, `version`, `released_at`, `notes`, `size_bytes`). An own product downloads with `product_id` + `file_id`, and its license is issued with `product_id` (field name assumed, see the contract).
- **License files for seller licenses.** `LicenseService.EnsureLicenseFilesAsync(token, licenses)` issues or renews (2 days before expiry) `Assets/StudioRaming_Onairdeck/<license name>/onairdeck.license` through `plugin-license { license_id, client }` for every license whose package is installed in the project by any route (`InstalledPackages.IsInstalled`: Packages folder, manifest.json, vpm-manifest.json). Called after a list refresh (`PurchaseWatcher`, `UpdateCheckService`) and after a license-version install; refusals go through `DeviceLimitNotice`.
- **Dependencies from the account first.** `CollectDependenciesAsync` resolves installed, then a license version of the account (same package name and version, device gate applies), then the trusted VPM listings (`DependencyResolver`). A missing one throws `DependencyUnavailableException` (`Kind`: NotPublishedYet or GetOnAtelierFirst). `InstallAsync` takes the caller license list (optional last parameter).
- **`PurchaseWatcher`**: refreshes on editor focus, window focus and every 5 minutes while the window is open (at most once per 60 s, signed in only, silent on failure); keeps seen entry ids per account in EditorPrefs (the first load marks everything seen) and raises `NewEntriesFound`.
- **`FavoritesStore`** (EditorPrefs, per signed-in user id, `Changed` event), **`ThumbnailCache`** (https only, 64 MB cap with oldest-first eviction, quiet failure), **`UpdateCheckService`** (once per editor session and every 6 hours, signed in only, one Console line, never installs) and **`BatchQueue`** / `BatchActions` (sequential, "2/3" progress, cancel after the current item, per-item results, device-limit and update-required refusals pause through `DeviceLimitNotice`, Unity packages import without the import window).
- **Device limit (client side).** Every request that carries a session token now sends `X-OnAirDeck-Device` (SHA-256 of `onairdeck-device-v1|` + `SystemInfo.deviceUniqueIdentifier`; the raw id never leaves the PC), `X-OnAirDeck-Device-Name` (computer name, 64 characters, URI-escaped) and `X-OnAirDeck-Device-Platform` (`Windows`, `macOS`, `Linux`). `Editor/Api/DeviceIdentity.cs` (Unity part) and `DeviceIdentityCore.cs` (pure part, headless-checked).
- **Error model.** Error bodies are read once in `ThrowIfFailed`: 409 `device_limit` becomes `DeviceLimitException` (refused licenses and the devices holding seats), 426 `manager_update_required` becomes `ManagerUpdateRequiredException`, any other failure one `ApiException` (status, server error code, short English message; the raw body is kept in `ResponseBody`, no longer in the message). 401 still means `SessionExpiredException`.
- **Devices API.** `OnAirDeckApi.GetDevicesAsync` and `ReleaseDeviceAsync` (`plugin-devices`); `LicenseEntry` gains `max_devices`, `devices_used`, `this_device`.
- **`DeviceLimitNotice`.** Download, package install, license issue (including the one after a download) and silent license renewal report a device-limit or update-required refusal into one observable state with the action to retry after a release, instead of only logging it. The window UI for it comes later.
- **Packaging.** `build_manager_packages.py` also writes `Atelier-Manager.unitypackage` (same bytes as the versioned file) so `releases/latest/download/Atelier-Manager.unitypackage` is a stable link. CompileCheck references `UnityEngine.TextRenderingModule` (the theme uses `FontStyle`).
- 11 more headless checks (device hash vector, name, platform, error parser).
- **DRM products shipped as .unitypackage (contract v8).** A license counts as installed when a VPM package of it is installed or an `atelier.product.json` with its `license_id` exists under `Assets/` or `Packages/` (`ProductMarkers`, one scan per refresh; hidden and `~` folders skipped; malformed markers ignored). An existing `onairdeck.license` under `Assets/StudioRaming_Onairdeck/` keeps renewing without a package (by the id inside it, in the folder it is in). A marker without a license file gets one on the next background ensure (no reactivate header). New public `OnAirDeck.UnityManager.AtelierManagerApi.RequestLicense(string licenseId)` for lock screens (called by reflection): opens the window, signs in if needed, issues that license as a user click, fire and forget, never throws; the last requested id is in `AtelierManagerApi.PendingLicenseId` for the window to select.
- **Unity floor lowered to 2019.4** (`package.json`). Editor and License assemblies compile with 0 errors on 2019.4.31f1 and 2021.3.18f1. `PackageInfo.GetAllRegisteredPackages` (feedback environment) and `Client.Resolve` (install, recovery) are guarded with `UNITY_2021_1_OR_NEWER` and have a folder-based fallback / rely on the refresh on older editors.
- **Review fixes.** A license file issued to another account (or PC, when the payload carries a device) is reissued; a background refusal no longer overwrites the retry a paused batch installed (retries chain, same-key ones replace each other); cancelling while an item runs no longer leaves the batch waiting after a refusal; long license names keep their id suffix; an account switch during a purchase request drops that response; Windows reserved names (CON, NUL, COM1...) get a `_` prefix; the seen-entries list keeps the newest 1000 keys.
- **Released device (contract v7).** `X-Atelier-Reactivate: 1` is sent only on requests a user click started (install, update, download, batch, the reactivate button). 409 `device_released` becomes `DeviceReleasedException`; background paths stay silent and `DeviceLimitNotice.Current.Kind == DeviceReleased` shows one bar (`DeviceReleasedText`, ko/en/ja) whose button runs `RetryAsync()`.
- **Inventory gate for old installs.** Sources 1-3 (config table, package.json `replacesAssetFolders`, product marker) never move a folder unless a product handler vouches (`ILegacyHandler`) or the package's own inventory (`atelier.legacyInventory`, provisional JSON `{"files":{path:sha256}}`) matches every file; otherwise the plan says "old install needs clean-up" with the folder and the unmatched paths. Source 4 (GUID) is unchanged.
- **Renewal refusals are readable.** `LicenseRenewalStatus.All/For/Changed`: per license the refusal code (`api.Code` or `http_<status>`), cleared on success, set by `EnsureLicenseFilesAsync` and `IssueSellerLicenseAsync`.
- **Install a non-VPM license version by id.** `LicenseVersionInstall.InstallAsync(token, license, version, licenses, onProgress, cancel, interactiveImport, userInitiated)`: `plugin-download { license_version_id }`, .unitypackage through `PackageImportQueue` (paths and GUIDs kept, no import window by default), zip extracted, license file issued afterwards. The server returns one file `{url,file_name}` without a hash; the Manager checks `file_size` where it has one.
- **Dev-only server override** under the compile define `ATELIER_DEV_SERVER` (EditorPrefs `Atelier.Dev.FunctionsUrl`, `Atelier.Dev.SiteUrl`, `Atelier.Dev.LicensePublicKeyPem`, `Atelier.Dev.DeviceSalt`; loopback http downloads allowed). Without the define the prefs are never read (Verification check).
- **MingToon legacy hand-off.** With the old `Assets/StudioRaming/MingToon` and no `Packages/com.studioraming.mingtoon`, a user click and a dialog start `MingToonLegacyCleanup`: both files of the license version (`...-update.unitypackage` and the package zip) are downloaded and checked first, the installer must say `managerCleanup: true`, then `ProjectSettings/MingToonInstaller/manager-request.json` is written and the installer imported. The Manager waits (reload-safe state in `Library/OnAirDeck`, no refresh, resolve or import), reads `manager-result.json` matched by `requestCreatedUtc`, installs the zip to `Packages/` after `LegacyRemovedForManager` and calls `Client.Resolve`. `LegacyHandoff.Status(package)` returns None, Pending, Done or Stopped(reason). Background and batch never start it. `OnAirDeckConfig.NeverMoveAssetFolders` (presets, generated files, installer, MLC) is never part of any move.

## [0.6.0] - 2026-10-27

Kind popup (Bug / Feature request / Question), a message of up to 4000 characters, an optional error code of up to 200, a toggle **Attach recent Console errors (N)**, the environment shown read-only before sending, **Send** (disabled while sending or while the message is empty or too long) and the result below it with a short reference.
